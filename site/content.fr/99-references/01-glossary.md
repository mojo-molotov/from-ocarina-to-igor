# 99.01&nbsp;—&nbsp;Glossaire

> Terminologie utilisée dans l'écosystème Ocarina. Sources d'origine entre parenthèses.

## Railway Oriented Programming (ROP)

| Terme                                                                             | Définition                                                                                                                                                  |
| --------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **ROP** (Wlaschin, F#)                                                            | Pattern fonctionnel&nbsp;: succès et échec sont deux _rails_ parallèles&nbsp;; un échec bascule le calcul sur le rail d'échec, où il reste (court-circuit). |
| **`Result[T]`**                                                                   | Union discriminée `Ok[T] \| Fail`. Erreur portée comme **valeur**, pas comme exception levée.                                                               |
| **`Ok[T]`**                                                                       | Wrapper de succès, `value: T`.                                                                                                                              |
| **`Fail`**                                                                        | Wrapper d'échec, `error: Exception`.                                                                                                                        |
| **`is_ok`, `is_fail`**                                                            | `TypeGuard` qui narrowent un `Result[T]` vers `Ok[T]` ou `Fail`.                                                                                            |
| **`Action[T]`**                                                                   | `Thunk[Result[T]]`&nbsp;—&nbsp;fonction sans argument qui rend un `Result[T]`.                                                                              |
| **`ActionStart[T]`**                                                              | État initial du builder d'action ROP. Attend `.failure(...)`.                                                                                               |
| **`ActionFailure[T]`**                                                            | Après `.failure(...)`. Attend `.success(...)`.                                                                                                              |
| **`ActionSuccess[T]`**                                                            | Après `.success(...)`. Attend `.execute()`.                                                                                                                 |
| **`ActionChain[T]`**                                                              | Après `.execute()`. Porte `has_failed: bool` et `result: Result[T]`. Permet `.then(...)`.                                                                   |
| **`NeutralActionStart[T]`, `NeutralActionFailure[T]`, `NeutralActionSuccess[T]`** | États _inertes_ du rail d'échec. Bouchonnent en ne faisant plus rien.                                                                                       |
| **`ChainRunner[T]`**                                                              | Encapsulation paresseuse d'un `ActionChain`. Exécutée par `.run()`.                                                                                         |
| **`drive_page`**                                                                  | Alias sémantique opinionated pour `chain_actions`. «&nbsp;_Prendre le contrôle d'une page_&nbsp;».                                                          |
| **`match_page` /&nbsp;`when`**                                                    | Branchement conditionnel. First-match wins.                                                                                                                 |
| **`create_act`**                                                                  | Primitive de bas niveau pour créer `act` (_pas de test_). Wrappée par le projet utilisateur.                                                                |
| **`act`** (côté projet)                                                           | Wrapper utilisateur de `create_act` avec hook `on_failure` spécifique au projet. Permet de représenter un _pas de test_.                                    |

## ISTQB /&nbsp;vocabulaire professionnels du test

| Terme                     | Définition                                                                                                         |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| **ISTQB**                 | International Software Testing Qualifications Board. Organisme professionnel du test logiciel.                     |
| **Test cycle**            | Niveau le plus haut. Une exécution complète.                                                                       |
| **Test campaign**         | Niveau sous le cycle. Non défini directement dans l'ISTQB mais reconnu dans le vocabulaire des testeurs de métier. |
| **Test suite**            | Niveau sous la campagne. Une collection de tests _exécutables_.                                                    |
| **Test case**             | Un cas de test. Unité atomique.                                                                                    |
| **Test step**             | Un pas de test. Action atomique dans un test case.                                                                 |
| **Smoke test**            | Vérification minimale qui prouve que le système est _en marche_. Si échec, le reste est inutile.                   |
| **Setup /&nbsp;Teardown** | Pré-condition /&nbsp;post-condition d'un test.                                                                     |

## Ocarina (orchestration)

| Terme                                     | Définition                                                                                                                           |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| **`Test[Driver]`**                        | Test ISTQB. Métadonnées +&nbsp;scenario factory +&nbsp;fragments +&nbsp;skip.                                                        |
| **`TestSuite[Driver]`**                   | Suite ISTQB. Parallélisation (_thread pool_), saturation, filtrage IDs, retries.                                                     |
| **`TestCampaign[Driver]`**                | Campagne. Séquence de suites avec config workers partagée.                                                                           |
| **`TestCycle[Driver]`**                   | Cycle ISTQB. Smoke (avec modes `fail-fast` vs `wait-for-all`) +&nbsp;main.                                                           |
| **`TestExecutor[Driver]`**                | Exécute une seule tentative d'un test. Stateless.                                                                                    |
| **`TestFlow[Driver]`**                    | Boucle de rejeu (1+max_retries) avec backoff linéaire.                                                                               |
| **`TestRunner[Driver]`**                  | Sortie de `Test.spawn(driver, logger)`. Agrégateur de chain_runners +&nbsp;setup +&nbsp;teardown +&nbsp;watchers.                    |
| **`Scenario[Driver]`** (frozen dataclass) | Encapsule `test_chain`, `setup`, `teardown`, `watchers`.                                                                             |
| **`TestChain`**                           | `Sequence[ChainRunner[Any]]`. La séquence à exécuter pour appliquer le test.                                                         |
| **`Watcher[Driver]`**                     | _Daemon thread_ pour observer quelque chose en plus sur un test. Callback périodique.                                                |
| **`Saturation`**                          | Mécanisme de clonage aléatoire de tests pour atteindre `max_workers`. Copies nommées `[COPY N] <name>` (ou `[+N]` selon convention). |
| **`Transient errors`**                    | Tuple d'exceptions qui déclenchent un rejeu.                                                                                         |
| **`max_retries_per_test`**                | Nombre de rejeux. Par défaut, 8 («&nbsp;_9 vies comme un chat_ 🐱&nbsp;»).                                                           |
| **`autoscreen_on_fail`**                  | Capture automatique de captures d'écran lors d'un pas de test en échec.                                                              |

## Ocarina (DSL invariants)

| Terme                                    | Définition                                                                                                  |
| ---------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| **`validate(value, name="...")`**        | Entry-point du DSL d'invariants.                                                                            |
| **`ValidationStartBlock[T]`**            | État initial. Attend `.assert_that(...)`.                                                                   |
| **`ValidationAssertBlock[T]`**           | Après `.assert_that(...)`. Accepte `.assert_that`, `.otherwise`, `.then`, `.execute`.                       |
| **`.assert_that(predicate)`**            | Ajoute un AND logique.                                                                                      |
| **`.otherwise(predicate)`**              | Ajoute un OR logique. Combine via `_any_of`.                                                                |
| **`.then(new_value)`**                   | Change la valeur en cours dans la chaîne. Conserve les erreurs accumulées.                                  |
| **`.execute()`**                         | Exécute la chaîne, retourne un `_ValidationResult` (inerte tant qu'on n'appelle pas `.raise_if_invalid()`). |
| **`chain_validations(*)`**               | Merge plusieurs `ValidationAssertBlock` en un seul.                                                         |
| **`InvariantViolationError`**            | Exception levée par les prédicats.                                                                          |
| **`AggregateInvariantViolationError`**   | Agrégation de plusieurs `InvariantViolationError`. Levée par `.raise_if_invalid()`.                         |
| **`DuplicatesError`**                    | Sous-classe d'`InvariantViolationError` levée par `has_unique_elements`.                                    |
| **`BusinessInvariantValidator.create`**  | Factory pour invariants métier.                                                                             |
| **`FrameworkInvariantValidator.create`** | Factory pour invariants framework.                                                                          |

| **`DriverBuilder[Driver]`**                                                            | Builder qui gère le profile tmp dir et produit `(driver, dispose)`.                                                                                                                 |
| **`BuiltWebDriver[Driver]`**                                                           | `tuple[Driver, Effect]`&nbsp;—&nbsp;driver + dispose.                                                                                                                               |
| **`Screenshotter[TDriver]`**                                                           | Utilitaire de capture thread-safe. Burst mode, healthcheck.                                                                                                                         |
| **`ScreenshotterConfig[TDriver]`**                                                     | Config (frozen dataclass)&nbsp;: output_dir, file_ext, health_check, save_full_page, etc.                                                                                           |
| **`ActCounter`**                                                                       | Interface. Compte les `act` appelés par tentative.                                                                                                                                  |
| **`ThreadsBasedActCounter`**                                                           | Implémentation thread-local d'`ActCounter`.                                                                                                                                         |
| **`ILogger`**                                                                          | Port (ABC) de logging. Méthodes&nbsp;: `debug`, `info`, `warning`, `error`, `critical`, `success`, `test_name`, `exception`, `raw`, `set_prefix`, `set_domain_taxonomy`, `cleanup`. |
| **`ITakeScreenshot[Driver]`**                                                          | Protocol `(driver, logger, category) -> None`.                                                                                                                                      |
| **`PrintLogger` /&nbsp;`FileLogger` /&nbsp;`PrintAndFileLogger` /&nbsp;`MutedLogger`** | 4 implémentations canoniques d'`ILogger`.                                                                                                                                           |
| **`driver_healthcheck(driver)`**                                                       | Ping `driver.title`&nbsp;; lève `DriverDiedError` si LE DRIVER EST DEAD.                                                                                                            |
| **`DriverDiedError`**                                                                  | Exception levée par `driver_healthcheck`.                                                                                                                                           |
| **`PageVerificationError`**                                                            | Exception levée par `POM.verify` quand la page n'est pas la bonne.                                                                                                                  |
| **`NoMatchingBranchError`**                                                            | Exception levée par `match_page` quand aucun `when` ne match.                                                                                                                       |

## Programmation fonctionnelle

| Terme                      | Définition                                                                                           |
| -------------------------- | ---------------------------------------------------------------------------------------------------- |
| **`Effect`**               | `Callable[[], None]`&nbsp;—&nbsp;fonction sans argument ni retour, déférée.                          |
| **`Thunk[T]`**             | `Callable[[], T]`&nbsp;—&nbsp;fonction sans argument, déférée.                                       |
| **`Closure`**              | Fonction qui capture un environnement.                                                               |
| **`Fold` /&nbsp;`reduce`** | Réduction d'une séquence à une seule valeur (_catamorphisme_).                                       |
| **`TypeGuard`**            | PEP 647&nbsp;—&nbsp;annotation qui _narrow_ un type côté _type checker_.                             |
| **`Discriminated union`**  | Union de types disjoints, discriminée par un test (typiquement `isinstance`).                        |
| **`Sealed union`**         | Discriminated union dont tous les variants sont `@final`.                                            |
| **`@final`**               | PEP 591&nbsp;—&nbsp;annonce qu'une classe ne peut pas être sous-classée (pas de covariance infinie). |
| **`Self`**                 | PEP 673&nbsp;—&nbsp;type de retour qui réfère à la classe instanciée (pas la classe déclarée).       |
| **`Protocol`**             | PEP 544&nbsp;—&nbsp;type structurel&nbsp;; tout objet avec la bonne shape est utilisable.            |
| **`PEP 695`**              | Generics syntax `class Foo[T]:` (Python 3.12+).                                                      |

## Idéologie Ocarina

| Terme                              | Définition                                                                                                                                                                                     |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Vilain (au sens hacker)**        | Identité revendiquée du hacker souverain qui agit hors institutions, par opposition aux conventions et au _branding corporate_. Le Vilain confronte le pouvoir mais respecte les plus faibles. |
| **Monster (au sens hacker)**       | Celui qui exploite techniquement sa compétence pour persécuter des personnes vulnérables (harceleur, doxeur, etc.). _Ennemi_ structurel de la vraie scène hackerss.                            |
| **Culture du tooling**             | Conviction que les bons outils techniques (Nmap, Wireshark, Metasploit, Burp, sqlmap, _et al._) bien écrits par des petites équipes valent mille présentations marketing.                      |
| **Tribal loyalty (scène hackers)** | Loyauté absolue intra-communauté&nbsp;+&nbsp;méfiance extrême envers l'extérieur. Tests d'admission longs, _vouching_ par membres établis, excommunication brutale en cas de trahison.         |
| **Eyes everywhere**                | Hyper-vigilance opérationnelle apprise dans le contexte _underground_ (admin IRC légalement responsable des actions de ses canaux).                                                            |

## IA, ML, RL

| Terme                           | Définition                                                                                                                                  |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| **LLM**                         | _Large Language Model_. Modèle Transformer pré-entraîné sur un large corpus. Claude, GPT, Gemini, Llama, Mistral.                           |
| **Transformer**                 | Architecture introduite par _Attention Is All You Need_.                                                                                    |
| **Foundation model**            | Modèle pré-entraîné réutilisé pour de multiples tâches via _fine-tuning_ ou _prompting_.                                                    |
| **RL (Reinforcement Learning)** | Apprentissage par interaction avec un environnement, guidée par un _signal de reward_. Sutton & Barto 1998.                                 |
| **Constitutional AI (CAI)**     | Méthode d'alignement Anthropic (Bai et al., 2022). Le modèle critique et révise ses propres réponses selon une _constitution_ écrite.       |
| **Probe**                       | Primitive d'apprentissage empirique pour l'IA.                                                                                              |
| **llms.txt, llms-full.txt**     | Standard Jeremy Howard (fast.ai), 2024. Index Markdown court (`llms.txt`) + doc full concaténée (`llms-full.txt`) pour ingestion par agent. |
| **SKILL.md**                    | Permet à un agent IA de plugger une compétence projet.                                                                                      |
| **CLAUDE.md**                   | Donne ensemble de règles à Claude Code.                                                                                                     |
